# 二、 硬體選型、電路設計與面板選擇

2.1 三大彩色電子紙面板規格與光學特性

InkTime 面板驅動層抽象支援以下三類面板 Profile：

1. safe_4c (通用 7.3 吋四色面板)

  • 支援色彩：Black (#000000), White (#FFFFFF), Red (#DC1E1E), Yellow (#F5BE19)
  • 像素格式：2bpp（1 Byte 存放 4 個像素；像素高位到低位打包）
  • 單張圖片大小：$480 \times 800 \times 2 / 8 = 96,000\text{ Bytes}$ ($93.75\text{ KB}$)
  • 物理特性：高對比度，黑白極為純淨，適用於明信片、月曆與高對比文字圖示版型。

2. gdep073e01_6c (GoodDisplay GDEP073E01 Spectra 6 六色面板)

  • 支援色彩：Black (#000000), White (#FFFFFF), Green (#199B46), Blue (#1E55AA), Red (#D22323), Yellow (#F0C319)
  • 像素格式：indexed4（4 bits/pixel；1 Byte 存放 2 個像素）
  • 單張圖片大小：$480 \times 800 \times 4 / 8 = 192,000\text{ Bytes}$ ($187.5\text{ KB}$)
  • 物理特性：Spectra 6 微膠囊技術，色彩飽和度高，為人像與風景照片之首選面板。

3. gdey073d46_7c (GoodDisplay GDEY073D46 ACeP 7 色面板)

  • 支援色彩：Black, White, Green, Blue, Red, Yellow, Orange (#F06E14)
  • 像素格式：indexed4 ($192,000\text{ Bytes}$)
  • 物理特性：增加了橙色（Orange）粒子，風景落日與膚色過渡更為平滑。

2.3 電池功耗模型與 ADC 分壓量測電路

電池量測電路 (Resistor Divider)

ESP32 ADC1 (GPIO 34 / GPIO 1) 透過兩個 $100\text{ k}\Omega$ 精密金屬膜電阻對 3.7V 鋰電池分壓：

$$V_{\text{ADC}} = V_{\text{BAT}} \times \frac{100\text{k}}{100\text{k} + 100\text{k}} = \frac{V_{\text{BAT}}}{2}$$

電壓計算公式：

CPP 
uint32_t raw_adc = analogRead(BATTERY_ADC_PIN);
float voltage_mv = (float)raw_adc * (3300.0f / 4095.0f) * 2.0f * ADC_CALIBRATION_FACTOR;

工作功耗統計模型：

  • Deep Sleep 待機電流：$\approx 10 \sim 15\,\mu\text{A}$
  • Wi-Fi 連線與 HTTP 下載：$120 \sim 240\,\text{mA}$ (持續 $2 \sim 4$ 秒)
  • 墨水屏 SPI 刷新寫入：$40 \sim 80\,\text{mA}$ (持續 $15 \sim 25$ 秒)
  • 單次刷新總能耗：$\approx 2.5\,\text{mAh}$。若搭配 $3000\,\text{mAh}$ 鋰電池且每日刷新 1 次，理論續航可達 8 ~ 12 個月。

3.2 韌體原始碼邏輯與驅動初始化序列

ink-display-7C-photo.ino 執行流程圖：

flowchart TD
    Boot["系統開機 (Boot)"] --> InitHW["初始化硬體 (Pins / SPI / ADC)"]
    InitHW --> ConnWiFi{"連接 Wi-Fi"}
    ConnWiFi -->|失敗| LaunchAP["開啟 AP 配網熱點 (180 秒)"]

E-Paper 驅動核心指令 (Command Sequences)

  • 0x01 (POWER SETTING)：設定內部 VCOM、VGH、VGL 驅動電壓。
  • 0x06 (BOOSTER SOFT START)：設定電荷泵軟啟動參數。
  • 0x04 (POWER ON)：啟動高壓發射。
  • 0x12 (DISPLAY REFRESH)：觸發物理粒子排列與色彩塗佈（阻塞直到 BUSY 腳位拉高）。
  • 0x02 (POWER OFF)：切斷高壓驅動。
  • 0x07 (DEEP SLEEP)：使面板進入 $1\,\mu\text{A}$ 休眠狀態。

3.3 燒錄、Wi-Fi 配網與自動配對流程

  • 燒錄韌體：

使用 esptool.py 燒錄編譯產出的 .bin：

BASH 
   esptool.py --chip esp32s3 --port /dev/ttyACM0 --baud 921600 \
     write_flash -z \
     0x0000 bootloader.bin \
     0x8000 partitions.bin \
     0x10000 ink-display-7C-photo.bin
  • 連線熱點配網：
  • ESP32 首次啟動會廣播 Wi-Fi 熱點：InkTime-XXXXXX；SSID 尾碼來自裝置識別，AP 密碼為每次啟動重新產生的隨機值，請以面板或序列設定畫面顯示為準。
  • 使用手機連線後，瀏覽器登入 http://192.168.4.1。
  • 輸入家中的 Wi-Fi SSID 與密碼，以及 InkTime 伺服器網址（例如 http://192.168.1.100:8765）。
  • 新自製裝置不要輸入 Token；儲存後由韌體向 /api/device/v1/pairing/request 取得短期配對碼，並在面板顯示。
  • 管理員在 Web「裝置」頁核對配對碼後按「核准配對」；韌體 claim 成功後只接收一次 Device Secret 與 credential version，寫入既有 A/B NVS。
  • 完成綁定：裝置之後以 Device Secret／version 呼叫 Manifest、Queue 與 Status，不需要登入 Session；撤銷或重新配對時 fail-closed。既有 Legacy Token 與 PhotoPainter Stock `/dataUP` 維持相容分流。

4.1 OpenAI 官方 Vision API 連接 (GPT-4o / GPT-4o-mini)

進入 Web 控制台 AI 提供者 (/providers) 點擊 [新增 Provider]，設定如下：

  • 名稱 (Name)：OpenAI-Official
  • Base URL：https://api.openai.com/v1
  • API Key：輸入 OpenAI 專用 sk-proj-... 金鑰（儲存時將自動經 Fernet 密碼學加密）
  • 模型名稱 (Model Name)：
  • 低成本第一階段模型：gpt-4o-mini
  • 高品質第二階段模型：gpt-4o
  • Token 價格設定：
  • gpt-4o-mini：Input $0.00015 / 1k tokens, Output $0.0006 / 1k tokens
  • gpt-4o：Input $0.0025 / 1k tokens, Output $0.01 / 1k tokens

4.2 本機 LMStudio 視覺大模型連接 (Qwen2.5-VL / Qwen3-VL)

若不想使用雲端付費 API，可透過 LMStudio 本機執行開源視覺大模型：

  • 開啟 LMStudio 下載並載入 Vision 模型（如 qwen2.5-vl-7b-instruct 或 qwen3-vl-8b）。
  • 在 LMStudio 開啟 Local Inference Server，埠號預設為 1234。
  • 在 InkTime 控制台新增 Provider：
  • 名稱：LMStudio-Local
  • Base URL：http://127.0.0.1:1234/v1 (若為 Docker 請設主機 IP，如 http://172.17.0.1:1234/v1)
  • API Key：lm-studio (填寫任意非空字串)
  • 模型名稱：qwen2.5-vl-7b-instruct
  • Token 價格：Input $0.00 / Output $0.00

4.3 Ollama 本機模型相容介面連接 (LLaVA / Qwen-VL)

若使用 Ollama 進行本機推論：

  • 啟動 Ollama 服務：ollama run qwen2-vl
  • Ollama 提供標準 OpenAI 相容介面 /v1：
  • Base URL：http://127.0.0.1:11434/v1
  • API Key：ollama
  • 模型名稱：qwen2-vl

4.4 Azure OpenAI 與自訂相容 Vision 端點

# 九、 10 種 Dithering 抖動演算法與色彩空間演算法數學原理

9.1 抖動演算法數學矩陣

1. Floyd–Steinberg 誤差擴散算法 (floyd_steinberg)

將當前像素量化產生的色差 $\Delta E = P_{\text{adjusted}} - P_{\text{palette}}$ 依以下比例分配給相鄰 4 個像素：

$$\begin{bmatrix}

& \bullet & \frac{7}{16} \\

\frac{3}{16} & \frac{5}{16} & \frac{1}{16}

\end{bmatrix}$$

2. Atkinson 抖動算法 (atkinson)

將色差 $\Delta E$ 的 $\frac{3}{4}$ 均勻擴散給 6 個相鄰像素（每處佔 $\frac{1}{8}$），保留更多純白與純黑區域：

$$\begin{bmatrix}

& \bullet & \frac{1}{8} & \frac{1}{8} \\

\frac{1}{8} & \frac{1}{8} & \frac{1}{8} & \\

& \frac{1}{8} & &

\end{bmatrix}$$

3. Bayer 4x4 與 8x8 有序抖動 (bayer4 / bayer8)

利用預設閥值矩陣 $M$ 對像素加入空間干擾頻率：

$$M_4 = \frac{1}{16} \begin{bmatrix}

0 & 8 & 2 & 10 \\

12 & 4 & 14 & 6 \\

3 & 11 & 1 & 9 \\

15 & 7 & 13 & 5

\end{bmatrix} - 0.5$$

4. 蛇形 Floyd–Steinberg 抖動 (serpentine_floyd_steinberg)

奇數行由左至右掃描，偶數行由右至左掃描，消除傳統誤差擴散的單向水波紋（Swarms/Worm artifacts）。

9.2 色彩距離空間：OKLab vs sRGB

sRGB 歐幾里得距離 (RGB Distance)

$$d_{\text{RGB}} = \sqrt{(R_1 - R_2)^2 + (G_1 - G_2)^2 + (B_1 - B_2)^2}$$

  • 缺點：忽略人眼對綠色波長敏感度遠高於藍色的非線性光學特性。

OKLab 感知均勻色彩空間 (OKLab Distance)

先將 sRGB 轉換為線性 Lightness ($L$), $a$ (紅綠軸), $b$ (黃藍軸)：

$$\begin{aligned}

L &= 0.210454 L' + 0.793618 M' - 0.004072 S' \\

a &= 1.977998 L' - 2.428592 M' + 0.450594 S' \\

b &= 0.025904 L' + 0.782772 M' - 0.808676 S'

\end{aligned}$$

在 OKLab 空間計算 Euclidean 距離：

$$d_{\text{OKLab}} = \sqrt{\Delta L^2 + \Delta a^2 + \Delta b^2}$$

  • 優勢：在墨水屏有限的 4 色 / 6 色面板上，相片人像膚色過渡更加自然，不會出現突兀的色彩塊斑。

# 十四、 全情境故障排除與問題診斷指南

14.1 網路連線與 ESP32 硬體故障排除

現象 1：ESP32 畫面顯示 HTTP 401 Unauthorized 或無法成功下載 Release

  • 可能原因：
  • 自動配對裝置的 Device Secret 或 credential version 已撤銷／失效，或 Legacy 裝置的相容 Token 不符。
  • HTTP 請求 Header 未帶入 Authorization: Bearer <credential>，自動模式也未帶 X-InkTime-Credential-Version。
  • 使用了舊版 URL query 金鑰（如 /bin?key=...），但伺服器 device.legacy_api_enabled 設定為 false。
  • 排除步驟與診斷：
  • 自動配對模式先在 Web「裝置」頁確認 pairing state，必要時按 [啟用重新配對]，再核對新的短期配對碼並按 [核准配對]。
  • Legacy 模式才使用相容 Token 重新產生流程；不要把 Device Secret 放入 URL、Log、截圖或手冊。
  • 若必須使用舊版 URL 金鑰，至 /settings 頁面將 device.legacy_api_enabled 切換為 true 並重啟 Web 伺服器。

現象 2：ESP32 下載時回傳 HTTP 404 Not Found

  • 可能原因：
  • 伺服器資料庫 render_releases 中尚未產生任何發布集。
  • ESP32 裝置設定的面板 Profile（如 safe_4c）與伺服器目前渲染發布的 Profile（如 gdep073e01_6c）不一致。
  • 排除步驟與診斷：
  • 進入 Web 控制台 / (儀表板) 點擊 [手動發布新畫面]，強制生成一組最新發布集。
  • 進入 /devices 檢查 ESP32 裝置的 Profile 設定，並至 /settings 確保 render.profile 設定兩者完全一致。

現象 3：ESP32 開機後不斷自動重啟，Serial 輸出 Heap Allocation Failed

  • 可能原因：
  • 編譯韌體時未啟用 PSRAM，導致 ESP32 SRAM 空間不足以容納 192KB 的圖片 Buffer。
  • 韌體中將 HTTP Client 設定為一次性將整份檔案 getString() 載入記憶體。
  • 排除步驟與診斷：
  • 檢查 Arduino IDE 工具選單或 platformio.ini，確保選擇了 OPI PSRAM 與 16MB Flash。
  • 確認韌體使用流式（Streaming/Chunked）讀取，分批透過 SPI 將 Payload 寫入墨水屏驅動 IC。

現象 4：ESP32 鋰電池續航不到 1 週即告耗盡

  • 可能原因：
  • 伺服器現場渲染速度過慢（> 5 秒），導致 ESP32 WiFi 保持全功率發射時間過長。
  • ESP32 刷屏完畢後未正確呼叫 esp_deep_sleep_start() 進入休眠。
  • 排除步驟與診斷：
  • 檢查背景 Scheduler 的 Pre-rendering 預先編譯功能是否正常，確保 ESP32 可在 0.2 秒內完成 HTTP 下載。
  • 連接 Serial Monitor，確認刷屏結束後有印出 Entering Deep Sleep for X seconds 訊息。

14.2 照片庫、磁碟與 NAS 掛載故障排除

現象 1：相片庫顯示 Missing 照片數暴增，或掃描器停止並警示「超過 Missing 門檻」

  • 可能原因：
  • NAS 網路硬碟 (SMB / AFP) 掉盤或網路連線中斷，導致 INKTIME_PHOTO_DIR 變成空目錄。
  • 相片磁碟資料夾存取權限變更（例如 Docker 容器內無權限讀取 /photos）。
  • 排除步驟與診斷：
  • 進入 /diagnostics 檢查照片路徑存取狀態，重新掛載 NAS 磁碟。
  • 在 /settings 檢查 scanner.missing_threshold_percent 預設 10% 安全門檻；確定磁碟掛載正常後，於 /schedules 手動觸發照片庫掃描。

現象 2：歷史上的今天永遠找不到照片，或特定格式的照片被忽視

  • 可能原因：
  • 照片的 EXIF 日期格式非標準 YYYY:MM:DD（如使用 ISO 8601 或斜線 YYYY/MM/DD），造成日期解析傳回空字串。
  • 照片被本機預篩選（截圖識別/低品質瑕疵/E6 面板失真）自動排除。
  • 排除步驟與診斷：
  • 點擊該照片詳情頁 /photos/{photo_id}，檢視 EXIF 欄位並點擊 [手動變更拍攝日期]。
  • 進入 /photos/excluded 檢查排除列表，點擊 [還原照片] 移除排除標記。

14.3 AI 模型分析與 Token 成本故障排除

現象 1：背景分析工作狀態顯示 budget_exceeded 並自動暫停

  • 可能原因：
  • 當日或當月累積消耗的 Token 費用達到了 budget.daily_stop 或 budget.monthly_stop 熔斷門檻。
  • 單一 Job 設定的預算上限（budget.job_default）已用盡。
  • 排除步驟與診斷：
  • 進入 /costs 檢視實時 Token 計費圖表。
  • 進入 /settings 適度調高 budget.daily_stop 與 budget.monthly_stop 數值。
  • 進入 /jobs 點擊 [恢復 (Resume)] 繼續執行工作。

現象 2：AI 分析日誌頻繁出現 VLM-003: 模型回傳無效 JSON 或 VLM-004: 欄位不符合 Schema

  • 可能原因：
  • 本機小模型（如 LMStudio / Ollama 執行的模型）未完美支援 Structured Outputs，輸出了 Markdown 包裹語法 ( `json )。
  • 模型回傳時遺漏了必填欄位（例如缺少 side_caption 或 reason）。
  • 排除步驟與診斷：
  • 更換支援 JSON Mode / Schema 的 Vision 大模型（例如 qwen2.5-vl-7b-instruct 或 gpt-4o-mini）。
  • 在 /settings 的 analysis.scoring_rules 提示詞中加強規範：「回應必須為單一 JSON 物件，嚴禁包含 Markdown 代碼塊標記」。

現象 3：呼叫大模型頻繁跳出 HTTP 429 Too Many Requests

  • 可能原因：
  • analysis.concurrency 設定過大，背景 Worker 同時向 LLM Provider 發送過多請求，觸發 API Rate Limit。
  • 排除步驟與診斷：
  • 進入 /settings 將 analysis.concurrency 由 4 降低為 1 或 2。

14.4 影像渲染與墨水屏顯示畫質故障排除

現象 1：實體墨水屏畫面人像膚色發黃、顆粒雜點極多或紅黃色塊突兀

  • 可能原因：
  • Dithering 演算法之誤差強度設定過高（render.dither_strength > 1.2）。
  • 色彩映射空間選擇了 rgb 歐幾里得距離而非符合人眼感知的 oklab。
  • 排除步驟與診斷：
  • 進入 /rendering 將 Dither 模式切換為 photo_smooth（照片平滑）或 floyd_steinberg。
  • 將 render.color_distance 切換為 oklab，並於 /simulator 進行 A/B 比對確認效果。

現象 2：墨水屏畫面出現嚴重舊圖殘影 (Ghosting) 或顏色發灰

  • 可能原因：
  • 相框放置環境溫度過低（< 15°C），導致墨水微膠囊粒子黏滯度上升。
  • 伺服器 render.profile 選錯（例如實際使用 gdep073e01_6c 面板，設定卻選為 safe_4c）。
  • 排除步驟與診斷：
  • 進入 /devices 確保每個 ESP32 綁定的 Profile 與實體面板型號一致。
  • 將電子相框移至常溫（20~25°C）環境，或於 Web 端點擊 [模擬實體刷新] 發送清屏指令。

現象 3：渲染正式發布時提示「缺字，發布已終止」

  • 可能原因：
  • 照片的短文案（side_caption）中包含目前中文字型檔（render.font_path）不支援的特殊生僻字或 Emoji。
  • 排除步驟與診斷：
  • InkTime 渲染引擎為確保畫面品質，禁止缺字回退為預設字型。
  • 於照片詳情頁 /photos/{photo_id} 修改短文案去除生僻字，或於 /settings 上傳支援完整 Unicode 範圍的繁體中文字型（如思源黑體）。

14.5 資料庫與鎖定競爭故障排除

現象 1：系統日誌出現 sqlite3.OperationalError: database is locked

  • 可能原因：
  • 有背景 Worker 或掃描器正執行長時間的 SQLite 寫入交易。
  • Gunicorn 部署了多個 Process，在無跨程序寫入鎖的情況下競爭寫入資料庫。
  • 排除步驟與診斷：
  • 確定系統均使用 ManagedConnection 進行連線。
  • 在 /settings 將 scanner.write_batch_size 由 1000 降低為 500，縮短單次 fcntl.flock 鎖定時間。

現象 2：熱備份還原失敗，提示 RESTORE-001: InkTime Web、Worker 或 Scheduler 尚未停止

PhotoPainter Enhanced 跨日離線生命週期

裝置端離線排程 API 只接受 target=current（預設）與 target=next；任意日期、+N 或 history 都會拒絕。current 回應包含由伺服器 IANA 時區計算的 next_target_start_epoch 與 next_schedule_prefetch_epoch，韌體不使用固定 UTC offset 猜測跨日。

Scheduler 將 today 與 tomorrow 分開判斷：today 仍有未來正式 Slot 才保留，tomorrow 在本地 prepare hour 與「明日第一 Slot 減 prefetch lead 與 server margin」的較早截止點準備。這避免明日已到技術截止時誤刪 today 尚未顯示的晚間 Slot。

韌體會先把明日 schedule、future rotation、button 與 config snapshot 寫入 staged_next.json，經 SHA、Queue identity、Slot epoch、Profile 與 config version 驗證後才完成 staged。active schedule 在午夜前不改；可靠 RTC 到達 target start 後再次驗證 target_start == active.target_end，以 .tmp／.bak rollback-safe 原子 promote，讓 00:00 Slot 可以正式顯示。

明日預取只回報 MANIFEST_RECEIVED、DOWNLOAD_STARTED、DOWNLOAD_COMPLETED、HASH_VERIFIED；真正面板刷新前不回報 display terminal ACK。local_next 是無網路預覽，不消費正式 Slot，也不清除 persisted retry。
