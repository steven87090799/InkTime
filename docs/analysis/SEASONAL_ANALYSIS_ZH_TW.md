# 歷年同期按需分析

在設定選擇 `analysis.execution_mode=seasonal_ai`，並設定可用 Vision Provider。
`analysis.seasonal_window_days` 預設前後 5 天，可改為 10 天，最多 31 天。
新安裝預設仍為 `local_only`；設定 API Key 不會自行啟用付費分析。

Scheduler 每五分鐘核對今天的同期範圍，初次啟用及掃描到新照片後均可補齊。
發布 Worker 也會先核對所需顯示日期（包含離線預備日期），等待同期工作結束才選片。
非當期新照片不提前分析；範圍跨年與閏日以固定閏年日曆計算。
沒有有效拍攝日期的照片會列出數量，需先補日期並重新掃描。

每個工作項目只含一張照片，不做多圖比較或追加模型選片。
每次最多排入 500 個不同內容，後續核對會接續補完；每日／每月的前 N 張策略
不會將當期照片悄悄改成本機分析。既有美元預算規則仍有效，阻擋時工作會暫停。
選片在日期窗口內優先未使用的照片，再依使用次數、既有評分與多樣性選擇，
包含自動配圖的第二張照片，不回退到窗口外照片。未使用優先不會改寫模型評分。
正式發布仍要求現有 v6 安全與方向證據；歷史舊 Schema 不會因而自動付費升級。

每張照片仍有原本的照片／分析資料列；相同 SHA-256 內容共用付費分析，副本沿用結果。
`seasonal_analysis_tasks` 保存歷次內容識別、照片、工作、狀態與結果快照。
任務登記與工作項目寫入同一個 SQLite transaction，並與即時／Batch 的保留機制互斥。
原有模型結果、AI Trace、付費操作 checkpoint 與用量紀錄繼續保留。
結果快照與歷次任務不會因全部重跑覆寫；照片同路徑被替換時，仍保留舊內容結果。
副本無法沿用時會留下去重通知，保留原內容的完成狀態與結果快照。

在「分析工作 → 歷年同期分析進度」查看當期覆蓋率、所有日期的逐張歷史及模型工作連結。
失敗或結果不明的項目不自動重試；Worker 租約失效也直接停止該項目。
管理員按逐張「手動重試」並接受可能再次計費後，才會建立新嘗試；原請求仍有有效租約時不能重送。
若已保存回應 checkpoint，仍優先還原回應。若供應商已收件而本機遺失回應，
手動重試可能重複計費，系統不宣稱供應商端 exactly-once。
失敗、暫停與缺日期會保持可見；全年覆蓋以每日持續運作及人工處理失敗為前提。

「全部重跑」涵蓋所有可處理照片（含非當期照片），忽略模型快取，三階段確認：

1. 伺服器預覽不同照片內容數與費用情境，建立綁定管理員、照片集合及模型規格的 10 分鐘確認。
2. 勾選再次計費並送出第二階段確認。
3. 輸入完整的「重新分析 N 張照片」才建立工作。原紀錄保留；同一確認重送只回傳同一工作。

照片集合或模型規格變更、確認過期、仍有分析工作或未對帳請求時拒絕建立。
費用估算是 Token 假設，價格未知時明確顯示未知，不視為預算上限。
排除、禁止上傳、已確認截圖、停用照片庫與尚未完成掃描的照片不會被送出。

CI 回歸：`tests/integration/test_seasonal_analysis.py`，由 provider、scheduler、persistence 與 web API owner suites 執行。
本模式不會在本機驗證時呼叫付費 Provider；NAS 部署與實際模型費用驗收另行進行。

## 與顯示歷史分支整合

整合版保留主分支 Migration 1–71，72 是顯示／選定次數與候選歷史，
73 是失敗通知，74 是同期任務與重跑確認。原始兩個 Draft 都使用 72，不能直接擇一保留。
升級器辨認季節分支原本的 72 名稱與完整欄位契約，在升級前備份後，
以同一交易將版本帳本及 migration history 對應改為 74，再補入 72–73；
任務、確認、結果快照及 ID 保留。顯示歷史分支的 72–73 直接追加 74。
同號但非已知契約會以 `MIGRATION-004` 停止啟動，避免將缺少的表或欄位當成已完成。
此相容處理限這兩個未發布 Draft；已發布的 1–71 migration 不變。
整合版資料庫不能交回舊分支執行，舊版會因不認識 74 而拒絕降級寫入。
