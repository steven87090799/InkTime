# 照片選片邏輯檢查與修復說明

更新日期：2026-09-05。此文件根據工作區程式與使用者提供的兩張畫面整理；未讀取線上照片資料庫。修復已寫入工作區，部署、Hosted CI 與實際模型文案品質尚未驗證。

## 結論與採用方案

舊系統不是單純把「本機＋AI」相加，而是混合加權、特殊加分、照片庫百分位、E6、最低回憶分、日期與播放歷史等多層規則。規則雖可重現，卻不容易理解，而且本機品質能過度影響選片。

採用「本機品質門檻 → AI 評分 → 依 AI 分數選片」。每張入選照片都須完成本機分析與有效 Schema v4 模型分析；品質不合格先排除，無須為已排除照片浪費 AI 分析。分析未完成代表等待，不代表零分。保留明確選擇的純本機模式、人工恢復、內容過濾與上傳／預算限制。

新公式：

```text
AI 基礎分 = 回憶分 × 67% ＋ 視覺分 × 33%
有效特殊等級 = min(4, 模型特殊等級 ＋ 最愛提升 1 級)
特殊加分 = [0, 2, 5, 9, 14][有效特殊等級]
AI 選片分 = min(100, AI 基礎分 ＋ 特殊加分)
```

本機在排序的權重為 **0%**，模型構成全部基礎分。67：33 約等於原本兩項 AI 指標的 2：1 比例，將本機的 25% 拿掉後重新分配；這是容易解釋、固定且符合需求的設計選擇，並非經實驗證明的最佳權重。最愛是使用者明確偏好，仍可提高特殊等級。

## 「暫用原始分」是什麼

舊程式至少需要 5 筆可排名分數，且至少 3 種不同分數，才換算照片庫相對百分位。條件不足時，直接使用原始綜合分，因此顯示「照片不足，暫用原始分」。這句話不是指原始模型 JSON，也不是缺少本機判斷。

舊的照片庫鑑別分為：`原始綜合分 × 35% ＋ 照片庫百分位 × 65%`。同分使用平均位置。這不是模型正確率，也不是統計信心水準；小樣本跨過門檻時，同張照片的顯示分可能突然改變，其他照片的加入也會改寫它的分數。這層已移除，介面改稱「AI 選片分」。

## 原本權重與兩張截圖的算式

| 項目 | 舊基礎分權重 | 新基礎分權重 | 判斷來源 |
| --- | ---: | ---: | --- |
| 一般回看價值（memory） | 50% | 67% | 模型 |
| 視覺吸引力（visual） | 25% | 33% | 模型 |
| 本機品質 | 25% | 0%，僅作門檻 | 本機特徵 |
| 特殊程度 | 額外 0–14 分 | 額外 0–14 分 | 模型等級＋最愛 |
| 照片庫稀有度 | 可能提升特殊等級 | 不使用 | 舊版由本機聚合 |
| 百分位 | 可能占鑑別分 65% | 不使用 | 舊版相對排名 |
| E6 適合度 | 最後顯示分預設占 20% | 不加權，僅參考 | 本機量測 |

第一張截圖：`55×0.50＋62×0.25＋100×0.25＋5 = 73`。

第二張截圖：`58×0.50＋62×0.25＋100×0.25＋2 = 71.5`。

這兩個分數都已含「本機品質 100」。舊版最後還會用 `鑑別分×80%＋E6×20%` 決定顯示分，所以畫面的 73／71.5 並不是完整的最後選片依據；另外還有日期、播放次數與多樣性調整。

如果沿用截圖中的模型分數與有效特殊等級，新分數分別是 **62.31** 與 **61.32**。下降是因移除了本機滿分貢獻，不是漏算；新舊分數尺度不能直接當作品質變差比較。如果原有效等級含已退休的稀有度提升，新分還會依實際模型等級與最愛狀態重算。

## 第二張為何沒有獨立本機卡片

詳細頁顯示的是「分析紀錄」，最多兩筆，優先保留現行模型與歷史模型結果。本機特徵存在照片資料上；保存模型結果時，同一筆分析也保存本機品質分，不必再新增一筆獨立本機分析。

因此「只有一張模型卡片」不等於「沒有做本機判斷」。截圖第二張已顯示本機品質 100。但只靠畫面不能證明掃描狀態在所有路徑都完成，所以新流程另外檢查 `local_features_status=complete`，同步 Vision 上傳、Batch 候選、自動選片與正式發布皆有對應檢查。詳細頁新增清楚的本機完成狀態，並指向下方逐項品質指標。

真正發現的漏選風險是舊版 `render.memory_threshold` 預設 **70**：截圖的 memory 55、58 即使綜合分超過 70，仍可能被這道獨立門檻排除。這道門檻已停用。自動候選不足時也不再把只有本機分析的照片補進來。

## 本機實際在算什麼

既有本機參考分依下式計算，最後限制在 0–100：

```text
sqrt(Blur score) × 3.2
＋ min(32, 對比 × 0.8)
＋ min(12, 短邊像素 / 100)
－ max(過曝比例, 欠曝比例) × 45
```

判為低優先時再扣 15；已排除時為 0。這個分數很容易飽和到 100，代表技術指標過關，不能解讀為完美照片或很值得回看。新自動 AI 排序不使用這個數值；保留作診斷與純本機模式使用。

品質門檻沿用共用的保守規則，例如：

- 嚴重模糊：Blur score < 60 **且** 對比 < 15。
- 解析度過低：短邊 < 240 px。
- 嚴重曝光問題：過曝／欠曝比例至少 92% **且** 對比 < 8。
- 極小且近乎空白：檔案 < 4096 bytes **且** 對比 < 8。

截圖、文件等既有內容用途規則與人工保護仍照原設定處理。疑似模糊、壓縮或社群轉存等不確定訊號不扣 AI 選片分。E6 是六色色盤轉換後的顯示參考，不能直接當成「看不清楚」的可靠證明，因此沒有再加入一個 E6 自動排除門檻。

## 模型標準與特殊程度

模型每次看送出的圖片，依固定輸出契約與可調整評分參考，輸出 memory、visual 與 special_level。伺服器只驗證格式、範圍與一致性，再合成排名；沒有另一個客觀量測器能證明 58 分比 55 分準確。

- **回憶分**：人物、互動、活動、日常紀錄、故事資訊量所形成的一般回看價值，不猜使用者私人的重要性。
- **視覺分**：構圖、光線、主體突出、色彩明暗、平衡與整體吸引力；不因女性、男性、孩子、寵物或旅行題材本身加分。技術模糊、解析度等由本機處理。
- **特殊程度**：事件或瞬間是否值得特別保留。重大事件主要放這一欄，提示詞要求避免與回憶分重複獎勵。

| 模型特殊等級 | 提示詞參考 | 加分 |
| --- | --- | ---: |
| 0 | 普通 | 0 |
| 1 | 稍有特色 | 2 |
| 2 | 明確活動、合照、旅行紀錄或難得互動 | 5 |
| 3 | 重要典禮、舞台、大型合照或難重現事件 | 9 |
| 4 | 極罕見人生里程碑或無法重現的重要紀錄 | 14 |

3、4 要保守使用。最多兩個 special_codes 是可查閱的情境標記，不另外累加。人潮不等於合照，不准推測這張在使用者照片庫稀有。舊版還會在至少 20 張其他照片、某標記占比 ≤5% 時增加一級；這種標記稀有未必有價值的推論已移除。

這套分數是啟發式偏好，並非科學測量。固定 Schema 能保障結構，不能保證模型理解正確；不同模型或服務商回覆可能有尺度差異。畫面記錄的是 `openrouter/free` 路由名稱，僅靠截圖無法確認每次背後的實際模型，因此也不能承諾跨次校準一致。新方案選擇讓規則透明，沒有再疊加一套看似精準的百分位去掩蓋不確定性。

## 「內容分類」那串 JSON

這是內容過濾檢查，與「旅行、人物、風景」等照片類型不同，也不是排名加分：

| 欄位 | 用途 | 預設判斷門檻 |
| --- | --- | --- |
| `sexualized_content` | 性暗示內容 | detected=true 且 confidence≥0.85 |
| `explicit_nudity` | 成人裸露 | detected=true 且 confidence≥0.85 |
| `female_glamour_portrait` | 刻意的女性單人寫真／glamour 呈現 | detected=true 且 confidence≥0.90 |

各類各有開關，任一啟用分類命中門檻才排除；`false` 不觸發。confidence 是模型自己回報的判斷信心，不是經校準的真實發生機率。普通女性旅遊照、自拍、日常與活動不能因「女性＋一個人」直接判為寫真。

介面已改成人話，例如「成人裸露：未標記；女性單人寫真：未標記」。有標記時再顯示信心；完整原始 JSON 仍可展開查閱。

## 文案修改

照片描述 caption 繼續客觀供搜尋；相框短句 side_caption 改為有文氣的口語旁白，從一個可見細節寫出小反差，帶一點冷幽默。避免逐項重述人物、光線、背景，避免故作深沉、人生雞湯、形容詞堆疊與半截比喻。

提示詞內的語感示例（不是已呼叫模型生成的新結果）：

- 等候欄杆：「欄杆負責認真，我們負責等」
- 正襟危坐：「正經先借一下，笑場晚點還」

示例只教寫法，禁止照抄或新增不在畫面中的事實。預設幽默調為 2／5、詩意 3／5，保留使用者明確改過的設定。短句仍為 8–16 字；提示詞要求超長就改寫完整的短句，不留下「像一場未說完」這種半句。現有儲存路徑沒有把它切成 16 字，截圖的不完整句子更像是模型自己完成在不完整的位置，不能靠放寬字數保證改善。

新的 prompt version 會區分後續分析／快取；既有短句不擅自改寫，也沒有在本次工作中呼叫付費模型。語氣是否符合喜好仍要以實際輸出驗收，無法只用程式測試證明「夠文青」。
