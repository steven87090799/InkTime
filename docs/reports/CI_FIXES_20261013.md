### 掃描器修復證據與阻擋條件

[Trivy 0.60 Debian detector](https://github.com/aquasecurity/trivy/blob/v0.60.0/pkg/detector/ospkg/debian/debian.go) 以 image OS major 查 advisory；FixedVersion 空白時直接認定 affected，不比較已安裝版本。所以單純加入已修 Forky 套件不足以消除 Trixie feed 的誤報。

`scripts/ci/debian_fixed_vex.py` 只為上述7個 CVE 的精確已修補套件生成 [OpenVEX fixed](https://github.com/openvex/spec/blob/main/OPENVEX-SPEC.md) 證據。需同時符合 raw scan 的 immutable image ID、Debian13、binary版本、source名稱／版本、PkgID、PURL 的名稱／版本／epoch／架構／distro。bsdutils 的 source epoch 依 Debian Source header 規則明確核對。舊版本、未審閱的新版本、未知 CVE、異常架構、缺 inventory 或來源不一致都不能產生 fixed 聲明。

`.github/workflows/container-security.yml` 對同一 immutable image 先保留完整未套用 VEX 的掃描，再使用同一快取 DB 和受驗證 VEX 交由 Trivy 原生判定。第二次結果與被判 fixed 的 finding 同時保存。所有其他 HIGH／CRITICAL、secret finding、scanner／證據錯誤仍失敗。`.trivyignore` 保持0個有效例外，未使用 ignore-unfixed 或全域忽略。`tests/unit/test_debian_fixed_vex.py` 覆蓋舊／未來版本、source、epoch、PURL、架構、未知 CVE、缺 inventory 與不同 image 的拒絕邊界。
